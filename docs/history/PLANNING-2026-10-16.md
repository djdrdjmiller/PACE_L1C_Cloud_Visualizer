# PACE visualization development decisions

This project will provide a local browser dashboard backed by Python for geographically referenced OCI and HARP2 L1C imagery, synchronized bin inspection, and reproducible publication figures. The developer handoff is prepared in `docs/HANDOFF.md`, with a starting prompt in `docs/DEVELOPER_PROMPT.md` and repository instructions in `AGENTS.md`. Implementation has not started. The scientific requirements below remain the detailed decision/reference record.

## Accepted choices

- Start with one matching OCI and HARP2 L1C granule pair and regional cropping, using original L1C bins for measurements and selection.
- Provide native SOCEA inspection and geographic map views. Verify native projection reconstruction against file geolocation.
- Use TOA reflectance for RGB imagery and OCI spectra, with a radiance toggle for spectra.
- Provide a saved fixed comparison stretch and a separate adjustable beauty preset. Display transforms do not alter scientific arrays.
- Use the OCI channel nearest 645 nm for the default red channel. Starting green and blue targets are 555 and 443 nm, pending scene inspection.
- Synchronize selection between instruments and retain selection when band/view controls change. Show missing data at the selected bin rather than silently selecting another location.
- Include a third linked map for HARP2 polarized reflectance or DoLP alongside OCI imagery and HARP2 total reflectance. Clicking any of the three maps updates the same original L1C-bin selection, all markers, and OCI/HARP2 diagnostics. Share projection, extent, crop, HARP2 channel/sector selection, and channel-mismatch reporting between the two HARP2 maps. Maintain quantity-specific display scales and correction status.
- Provide polarized-reflectance magnitude and signed scattering-plane Q/U, with scattering-angle and nominal-view-angle axes.
- For cloudbow and RFT comparison displays, apply the user's preferred negative sign flip relative to the canonical database/fitting signal to both observations and modeled curves. Label the plotted convention explicitly; retain canonical values and coefficients. Polarized-reflectance magnitude remains nonnegative.
- Select the nearest HARP2 sector within each wavelength, expose actual angles and mismatches, and retain all red views for single-band images and polarimetric curves.
- Export individual maps, paired maps, and maps with diagnostic panels to PNG and PDF. Save input provenance and display settings for reproduction.
- Display both angular branches separately and fit one at a time, initially selecting the branch with better valid angular coverage. The standard GPC product retrieves only its selected branch; fits on the other branch are exploratory and must be labeled accordingly. Identify the operationally selected branch when product metadata or verified algorithm logic permits; do not assume our coverage-based default establishes its identity.
- Release the core dashboard and acquisition tool first, stored GPC cloudbow-fit overlays second, and advanced RFT mixture fitting and above-cloud transmission correction afterward.
- Deliver the project as a shareable GitHub repository containing the Python library, local browser dashboard, companion acquisition tool, documentation, and reproducibility support. Repository creation and publication will be handled during implementation; no GitHub repository has been created yet.

## Companion acquisition tool

Add a separate Python discovery and download utility to the implementation scope. It will populate a local data cache and a scene manifest that the visualization tool can consume without catalog access.

The five development cases are:

1. Primary science scene with cloud, ocean, and coastline where possible.
2. Broad multi-angle HARP2 coverage, including changing view-dependent valid footprints.
3. OCI equatorial tilt transition.
4. Dateline crossing.
5. High latitude.

Each case has configurable region and time bounds. Search results are candidates until file inspection confirms the case: bounding-box overlap alone does not establish usable HARP2 RGB coverage, an OCI tilt transition, or a dateline crossing. One scene can satisfy multiple cases; cache each granule once.

Proposed workflow:

- Discover OCI L1C and HARP2 L1C candidates through Earthdata/CMR using earthaccess, recording collection versions and source identifiers.
- Rank candidate matches by common grid/source identifiers when available, overpass/time correspondence, and regional overlap. Verify geolocation and coverage after download; do not pair solely by filename or array shape.
- List candidate sizes and expected download volume before bulk acquisition. Authenticate through the user's Earthdata login; do not save credentials in manifests.
- Download complete original NetCDF products into data/raw, reuse verified cached files, and record completion/integrity information. Failed transfers must not appear as complete inputs.
- Store scenario membership, file paths, actual versions, times, bounding regions, matching evidence, and validation status in a manifest under data/manifests.
- Inspect metadata and selected array slices to classify each candidate. Report cases without qualifying data rather than substituting an unsuitable scene.
- Offer matching HARP2 CLOUD_GPC download for future features, treating unavailable GPC as optional to the L1C core.

The handoff supplies adjustable starting regions/windows, a 10 GiB download budget, up to three candidate pairs per case, one qualifying pair per case, and GPC inclusion when available in `config/development-scenes.yaml`. These are engineering defaults rather than already discovered scenes. Acquisition code and scene downloads have not yet been implemented.

## HARP2 channel interpretation and RGB proposals

Build a channel table from each L1C file's sensor_views_bands metadata: source view index, wavelength, nominal sensor_view_angle, and any supplied sector identifier/name. Preserve source identity while grouping channels by wavelength. Resolve dimensions by name and explicitly remove only identified singleton spectral axes. Decode fill values, scale factors, units, and quality metadata before scientific calculations.

The Help Hub L1C example contains all 90 channels in one product; it uses wavelength and nominal-view-angle variables to interpret the combined axis. Separate collection shortnames for individual sectors are not established by the inspected examples. Retain provided sector names when present; generated wavelength/angle labels must not be presented as official names.

Proposed default RGB control: use the approximately ten sectors of a sparse visible band as angle anchors and select nearest sectors in the other two visible bands. Prefer green as the anchor for true color; choose a sparse participating band for false color. Avoid a default slider containing all 60 red angles. Advanced controls can select individual sectors independently.

Proposed warning: flag a maximum nominal-angle span across RGB channels greater than 5 degrees; show all actual angles for every composite. This is a display policy, not a NASA scientific equivalence criterion. Check it against the actual L1C sector table before approval. Do not interpolate angular measurements or choose different source sectors at different pixels to conceal missing coverage.

Nominal along-track sector angles are distinct from per-bin sensor zenith and scattering angles. The selected-bin inspector must show the latter independently. RGB presets do not restrict the full angular sampling in polarimetric diagnostics.

## HARP2 polarimetric imagery and geometry

Provide a switchable third HARP2 map tied to the total-reflectance map. Proposed modes are polarized-reflectance magnitude RGB, DoLP RGB, and a signed scattering-plane reflectance map using the user's negative display convention. For a signed single-band map, use a zero-centered diverging scale; do not silently discard negative values to make a positive RGB. Additional signed RGB encoding can be specified after inspecting real scenes.

Compute polarized magnitude from the uncorrected Stokes reflectances: R_pol = sqrt(R_Q² + R_U²). Keep its nonnegative magnitude distinct from the signed cloudbow quantity. Use product DoLP after decoding/validation or derive it from original Stokes values with valid positive I; exclude undefined ratios. DoLP must never be recomputed using transmission-corrected total reflectance while retaining uncorrected Q/U. Preserve quality indicators and show low-signal limitations in the inspector. Default DoLP display can use a reproducible 0–1 range without clipping stored scientific values.

Polarimetric imagery uses the same approximately matched wavelength/sector triplets as the total map but has its own saved stretch. A fixed comparison stretch and an adjustable beauty preset remain available. Scalar modes expose a colorbar; RGB exports record each channel and its transfer function. Optional scattering-angle contours are based on a clearly identified band/view, with all selected-channel geometry accessible in the inspector.

Source-based display precedents: EUMETSAT's 3MI gallery pairs total and polarized RGB images, typically using 670/555/443 nm. CNES describes interpreting POLDER polarized imagery alongside scattering-angle contours. An EUMETSAT PACE-SAT3 presentation uses HARP2 polarized intensity (DoLP times I), including 865/550/440 and 865/670/440 RGBs. Some presentation images explicitly include Rayleigh correction. Our initial polarimetric images remain TOA and uncorrected; exact EUMETSAT tone-mapping parameters are not established by these sources.

Current HARP2 total reflectance is uncorrected. Retain a future optional transmission-only correction for total reflectance, with the OCI 0.64 entry as a proxy for HARP2's shorter visible bands. Keep this approximation explicit per channel, and establish mapping for other HARP2 bands separately. Evaluate transmission separately for each original L1C bin and selected view using actual geolocation_data solar_zenith_angle and sensor_zenith_angle, with mu_eff = mu0 * mu / (mu0 + mu). Never use the nominal sector angle for transmission. The supplied OCI LUT is an approximate cross-instrument correction, not a HARP2 band-response-specific table.

OCI generally has one valid observation geometry per bin; use that bin's valid-view geometry. It can vary across the swath, so do not replace it with a scene-wide constant. HARP2 adds the selectable multi-view dimension and its view-specific solar geometry.

Do not atmospherically correct HARP2 Q/U, signed polarized reflectance, polarized magnitude, or DoLP in this roadmap stage. Total-reflectance correction controls must not propagate to the polarimetric quantity. Label total and polarimetric panels with their respective correction states and preserve uncorrected observations for all cloudbow/RFT fitting.

Retain a research option for future polarized gas correction and modeled molecular/Rayleigh correction. The POLDER cloud Rayleigh-pressure algorithm uses gas-corrected Stokes parameters and separates component contributions before magnitude; it estimates cloud pressure rather than providing a general cloud-reflectance correction. An AirHARP study applies band- and geometry-specific gas corrections to I/Q/U using vector radiative transfer under experiment-specific atmospheric assumptions. Equal scalar transmission applied to all three Stokes components leaves DoLP unchanged, but this does not validate using the OCI cloud LUT for HARP2 polarization. The user agreed to this distinction; polarized correction is not included in the approved implementation milestones.

Validate identical source-bin selection from all three map panels, view-dependent transmission from pixel geometry, correction toggles leaving polarimetric arrays unchanged, and consistent markers/selection when the third map has missing data. A selection remains valid even where one panel has no observation; show that absence explicitly.

The supplied NetCDF LUT was inspected directly. It contains P21 on dimensions scattering angle (661), effective variance (27), effective radius (60), and wavelength (6). Actual radii cover 3.0 to approximately 53.369 micrometers; variances cover approximately 0.001504 to 0.497512. Actual wavelengths are approximately 0.355, 0.443357, 0.532, 0.548974, 0.664604, and 0.863359 micrometers. Coordinate arrays govern supported interpolation bounds, not the broader valid_min/valid_max attributes. The table includes scattering and extinction cross sections and parameter derivatives.

The base script performs an unweighted LUT grid search followed by local refinement using bilinear interpolation in log radius and log variance. For fixed microphysics, the fit is linear in A, B, and C: F(theta) = A P21(theta) + B [cos(theta)^2 - 1] + C. The weighted version applies inverse sample-count weights within scattering-angle bins, default width 2 degrees, both in the grid search and refinement, and uses weighted goodness-of-fit statistics. Use the base version as the starting reference; angular-density weighting is a separate optional experiment, not measurement-uncertainty weighting.

Resolve reference inconsistencies before numerical reproduction:

- The notebook deliberately overwrites the standard reflectance arrays in a test cell omitting Sun-Earth distance squared. Default scientific reflectance follows the PACE convention; validate the normalization used by each operational GPC version before comparing its stored coefficients.
- Early and late notebook cells use different signal/sign formulations. The user has selected a negative display flip relative to the database/fitting convention. Define the canonical fitting signal and explicit plot transformation, apply the same transformation to observations and all curve components, and validate against a reference notebook plot rather than inferring sign from variable names or labels alone.
- The notebook uses intensity_f0 for Q/U. Verify the appropriate polarization solar-irradiance metadata and agreement with the operational convention.
- The notebook splits angular samples at their scattering-angle turning point and can fit each side separately. Preserve original sector/view ordering for branch identification; sort only within a branch for angle interpolation. A turning-point split is a reference heuristic to validate against geometry and operational selection.
- The nearest-LUT helper, refined log-space interpolation, and early linear interpolation are distinct policies. The helper also excludes the upper angular endpoint while precomputed arrays include it. Operational reconstruction should adopt verified operational interpolation and bounds; exploratory fitting should record its chosen policy.
- Returned fit closures interpolate over observation angles using np.interp, which requires increasing angle coordinates. Evaluate dense curves from the LUT directly rather than from unsorted observations.
- Prefer least-squares solvers on the design matrix over solving normal equations. Check rank, fit support, zero-variance signals, invalid inputs, bounds, and optimizer convergence. Three samples can solve three coefficients but provide no residual degrees of freedom and do not establish a reliable microphysical retrieval.

Retain the requested advanced feature: obtain RFT mode 0 and mode 1 effective radius, effective variance, mode fractions, and RFT quality fields from GPC. Construct their phase-function mixture and fit it to observed polarized reflectance using a cloudbow-style parametric background.

Verify the product's fraction/phase-function normalization convention so the implementation preserves the weighting used by the original retrieval. Map the supplied LUT's p21 to the required P12 sign and normalization explicitly. Preserve reported mode identities and handle missing modes, invalid fractions, out-of-LUT microphysics, and nearly identical phase functions explicitly.

Label this output as an experimental RFT-constrained parametric fit. It is distinct from reconstructing the stored cloudbow fit and is not established as reproduction of the operational RFT algorithm. Independent mode amplitudes are outside the chosen feature scope.

Start reconstruction and exploratory fits on demand at the selected bin. Display each component, the mixture, observations, residuals, included sectors, angular branch, and fit support. Do not automatically merge both branches or perform scene-wide microphysics retrievals. Fit the uncorrected polarimetric observations; any future polarized atmospheric correction requires a separate scientific decision.

## Supplied OCI transmission table

User-supplied Chimaera OCI cloud-retrieval table: `Transmittance_OCI.hdf`. Inspected directly as HDF4 using the existing miniforge Python pyhdf installation. No algorithm or retrieval code was executed.

The file contains:

- Cloud_Top_Pressure: 10 coordinates from 100 to 1000 in steps of 100.
- View_Angle_Cosine: 20 coordinates from 0.05 to 1.0.
- Precipitable_Water: 53 coordinates from 0 to approximately 8.6, with nonuniform spacing.
- Wavelengths: 8 coordinates approximately 0.64, 0.86, 0.94, 1.20, 1.38, 1.60, 2.10, and 2.23.
- Transmittance, counts, and Standard_Deviation: shape (8, 20, 53, 10), consistent with wavelength, angle cosine, precipitable water, and cloud-top pressure axes.

The datasets have no units or descriptive attributes and the file has no global attributes. The user supplied the reader conventions: cloud-top pressure is in hPa, precipitable water is above-cloud water in g/cm², and the angle lookup uses mu_eff = mu0 * mu / (mu0 + mu), where mu0 and mu are solar- and sensor-zenith cosines. This effective path already represents downward times upward transmission. Bands are fixed algorithm indices, not an interpolatable spectral coordinate; legacy wavelength labels are retained for provenance. The supplied ratio experiment identifies indices 5, 6, and 7 as OCI 1615, 2130, and 2260 nm, despite legacy 1.60, 2.10, and 2.23 labels.

Transmittance includes -1 entries. Each wavelength has 3540 cells with nonnegative transmission and positive counts out of 10600 cells. There are 1120 negative-transmission cells across the full table with positive counts, so counts alone do not establish validity. The correction must mask unsupported entries and avoid interpolation through invalid cells. Retain counts and standard deviations for diagnostics; establish any minimum support criterion from the algorithm rather than inventing one.

Accepted temporary RGB approximation: use band index 0 (legacy 0.64 label) for the OCI approximately 645 nm red channel and as a proxy for both blue and green channel transmission. Expose this as an approximate RGB correction and record the proxy for each channel in exports and saved recipes. Retain actual source wavelengths. Do not extend this approximation silently to the entire OCI spectrum or custom false-color channels. Other correction mappings follow the algorithm's fixed band indices.
